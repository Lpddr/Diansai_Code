# 25E 项目前两项职责：代码实现与面试讲解

## 1. 修改范围与硬件关系

本次只对应简历前两项修改代码和说明，第三项视觉 UART DMA 接收方案不做结构调整。

实际硬件关系如下：

- WIT IMU **物理安装在云台上**，但接入 MSPM0 的 `UART_WIT`，因此 `wit_data.gz` 表示云台 Z 轴角速度。
- 左右轮编码器接入 MSPM0，用轮速差反映底盘的转动趋势。
- MSPM0 通过 UART0（工程中名为 `UART_CH340`）向 STM32 UART4 上报云台角速度、编码器差速和拐点序号。
- STM32 通过 USART2 向云台步进电机发送速度指令。

传感器接在哪块控制板上，不等于传感器物理安装在哪个机构上。本项目中 IMU 虽由 MSPM0 采集，但它仍然是云台角速度反馈传感器。

## 2. 第一项：应用—服务—驱动分层与周期调度

### 2.1 三层代码对应关系

| 层次 | STM32 云台端 | MSPM0 采集/底盘端 | 主要职责 |
|---|---|---|---|
| 应用层 | `My_App`、`Core/Src/main.c` | `MyApp`、`empty.c` | 模式控制、PID应用、循迹、按键和菜单逻辑 |
| 服务层 | `My_Service/task_service.*`、`motion_fusion_service.*` | `Service/chassis_motion_service.*` | 周期任务封装、板间数据解析、传感器状态管理和控制量融合 |
| 驱动层 | `My_Driver/Emm_V5.*`、HAL及组件 | `Driver`、TI DriverLib | UART、DMA、IMU、编码器、电机和OLED等硬件访问 |

### 2.2 调度器的准确性质

当前实现是**基于系统 Tick 的裸机协作式周期任务调度器**，不是抢占式“时间片轮转调度器”：

- SysTick或毫秒计数器提供时间基准；
- 主循环遍历任务表，到期后调用对应任务；
- 任务之间没有抢占和上下文切换；
- 每个任务必须短小并主动返回。

程序仍保留 `while (1)` 作为常驻主循环。因此，准确说法是**替代传统 `while(1)` 内的无序、无周期业务轮询**，而不是笼统地说“替代死循环”。

### 2.3 当前任务周期

STM32 云台端：

| 周期 | 任务 | 作用 |
|---:|---|---|
| 1 ms | `Vision_Service_Task` | 检查并解析新的视觉DMA帧 |
| 2 ms | `Chassis_Service_Task` | 接收云台IMU及底盘编码器遥测 |
| 5 ms | `Gimbal_Control_Service_Task` | 执行视觉位置外环、IMU角速度内环和编码器前馈 |
| 10 ms | `Key_Task` | 按键扫描及边沿处理 |
| 50 ms | `Menu_Run` | OLED菜单和状态刷新 |
| 100 ms | `MotionFusion_HealthTask` | 检查运动遥测是否超时 |

MSPM0 端：

| 周期 | 任务 | 作用 |
|---:|---|---|
| 5 ms | 编码器更新、`ChassisMotion_Update5ms`、`PID_Task` | 由1 ms硬件定时器五分频，更新运动量并完成底盘速度闭环 |
| 10 ms | `ChassisMotion_TelemetryTask` | 100 Hz上报云台IMU角速度、编码器差速及拐点序号 |
| 10 ms | 灰度、按键和串口任务 | 采集、事件及通信处理 |
| 50 ms | `Oled_Task` | 低频状态显示 |

### 2.4 简历推荐表述

> （1）设计 **“应用—服务—驱动”分层架构**，基于 **SysTick 实现裸机协作式周期任务调度**；将视觉解析、底盘通信、云台控制、按键及 OLED 等任务按 **1/2/5/10/50/100 ms** 周期组织，并由 **1 ms 定时器派生 5 ms 底盘速度闭环**，替代传统 `while(1)` 内的无序轮询，解耦控制链路与低频交互任务。

## 3. 第二项：视觉—IMU—编码器融合控制器

### 3.1 实际控制结构

```text
视觉目标坐标 ──> 位置外环PID ──> 期望云台角速度 ──┐
                                                  ├─> 角速度内环PID ──┐
云台IMU gz ─────────────────────> 实际云台角速度 ──┘                  │
                                                                     ├─> 电机速度指令
左右轮编码器差速 ──> 低通滤波与增益映射 ──> 车体转动前馈 ────────────┘
```

对应控制关系：

```text
e_position = x_target - x_vision
omega_target = PID_position(e_position)

e_rate = omega_target - omega_imu
u = PID_rate(e_rate) + LPF(K_encoder * (v_right - v_left))
```

- **视觉位置外环**负责消除目标中心与准星之间的像素偏差，其输出不再直接作为最终电机指令，而是作为期望云台角速度。
- **IMU角速度内环**使用安装在云台上的 `gz` 反馈，使云台快速跟踪外环给出的期望角速度，并抑制底盘传递到云台的机械扰动。
- **编码器前馈**利用左右轮速差预判车体转动趋势，在视觉误差和IMU反馈完全体现扰动前提前补偿。

这才是严格意义上的“视觉位置外环—IMU角速度内环”串级PID，而不是把视觉PID、IMU和编码器三个量简单相加。

### 3.2 代码调用关系

1. MSPM0 的 WIT UART DMA 中断解析 IMU数据，更新 `wit_data.gz`。
2. 5 ms定时任务调用 `ChassisMotion_Update5ms`，同步保存云台角速度和左右轮编码器差速。
3. `ChassisMotion_TelemetryTask` 每10 ms发送一帧：

   ```text
   $M,<gimbal_gyro_z×10>,<right_speed-left_speed×10>,<corner>#
   ```

4. STM32 UART4 DMA接收后，由 `Chassis_Service_Task` 和 `Parse_M0_Data` 更新 `motion_fusion_service`。
5. STM32每5 ms调用 `Cascade_Gimbal_Control`：先计算视觉位置外环，再计算IMU角速度内环，最后叠加编码器前馈并限幅。
6. 连续50 ms收不到遥测时，控制器清除角速度内环历史状态并退化为原视觉位置环，避免无效IMU反馈造成失控。

### 3.3 参数与实车整定

角速度内环初始参数位于 `STM32F407VET6/My_App/pid_app.c`：

- `X_rate_para.kp/ki/kd`：云台角速度内环参数；
- `X_rate_para.limit`：最终电机速度指令限幅。

传感器方向与编码器前馈参数位于 `STM32F407VET6/My_Service/motion_fusion_service.h`：

- `GIMBAL_IMU_RATE_SIGN`：IMU角速度反馈方向；
- `ENCODER_BODY_FF_SIGN`：车体运动前馈方向；
- `ENCODER_BODY_FF_GAIN`：编码器差速到云台电机补偿量的映射系数；
- `ENCODER_BODY_FF_LPF_ALPHA`：编码器前馈低通系数；
- `ENCODER_BODY_FF_LIMIT`：前馈输出限幅。

当前数值是保证代码结构完整的保守起调值，不应直接当成最终实车参数。正确整定顺序是：

1. 暂时关闭编码器前馈和视觉外环，只调IMU角速度内环；
2. 确认给定正角速度时云台方向正确，IMU反馈为负反馈；
3. 固定内环参数，再调视觉位置外环；
4. 最后逐步增加编码器前馈增益，确认底盘左右转动时补偿方向相反；
5. 进行静止、匀速、转弯和连续目标切换测试。

### 3.4 简历最终表述

> （2）设计 **“视觉—IMU—编码器”融合控制器**：以**视觉坐标偏差作为位置外环输入**，采用**位置环—角速度环串级 PID 控制**，以**云台 IMU 角速度作为内环反馈**，并引入**基于左右轮编码器差速估计的车体转动量作为前馈补偿**，有效抑制车体运动对云台的干扰，实现动态连续打靶。

面试时如果被问“融合体现在哪里”，可以回答：视觉决定目标位置误差，云台IMU闭合快速角速度反馈环，编码器差速提供车体运动前馈；三者分别作用于外环、内环和前馈通道，并不是把三路传感器数据直接做平均。
